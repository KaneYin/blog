在一个具有自我保护能力的程序中，断言很常用。
# 断言的概念
假设你确定满足某个特定属性，并且代码依赖于这个属性。例如，可能需要计算一个数值：
```java
double y = Math.sqrt(x);
```
我们确定这里的 x 是一个非负数。不过，可能还是想要再做一次检测，不希望计算中存在“不是一个数” (NaN) 浮点值。当然，也可以抛出一个异常：
```java
if (x<0)
	throw new IllegalArgumentException("x<0");
```
即使测试完成以后，这个测试片段还保留在程序中。如果程序含有大量的这种检查，程序运行起来就会比应有的速度慢一些。

**断言机制允许在测试期间在代码中插入一些检查，而在生产代码中自动删除这些检查**
Java 语言有一个关键字 assert 。这个关键字有两种形式：
`assert condition;`
和
`assert condition: expression;`

==这两个语句都会计算条件（condition），如果结果为 false，则抛出一个 AssertionError 异常。在第二个语句中，表达式（expression）将传入 AssertionError 对象的构造器，并转换成一个消息字符串。==

想要断言 x 是一个非负数，只需要使用下面这条语句：
```
assert x >= 0;
```

或者将 x 的具体值传递给 AssertionError 对象，以便以后显示：
```
assert x >= 0: x;
```
# 启用和禁用断言

**在默认情况下，断言是禁用的。** 可以在运行程序时用`-enablessertions` 或 `-ea` 选项启用断言：
```
java -enablessertions MyApp
```
注意，不必重新编译程序来启用或者禁用断言。启用或禁用断言是类加载器的功能。禁用断言时，类加载器会去除断言代码，因此不会降低程序运行的速度。
