# 为什么要使用泛型程序设计

泛型程序设计意味着编写的代码可以对多种不同类型的对象重用。

# 泛型

【例子】现在需要统计学生成绩，要求设计一个 score 类，包括课程名称、课程号、课程成绩，但是成绩分为两种，一种是`优秀、良好、合格` 另一种是 `60、70、90` 来表示，应该如何设计这样一种 score 类型呢？
```java
public class Score{
	String name;
	String id;
	Object value; //因为 Ocject 类型是所有类型的傅雷，因此可以存放 Integer 类型也可以存放String 类型

	public Score(String name, String id, Object value){
		this.name = name;
		this.id = id;
		this.value = value;
	}

	public getValue(){
		return this.value
	}
}
```
以上的方法虽然很好的解决了多种类型存储的问题，但是 Object 类型在编译阶段不具有良好的类型判断能力，很容易出现下面的情况：
```java
public void main(String[] args){
	 //成绩是 String 类型的
	Score score = new Score("数据结构与算法“，”EP001“，”优秀“);
	// 成绩是 Integer 类型的，注意这里发生了 自动装箱 int -> Integer
	Score s = new Score("高等数学","EP002",90);
 
}
```

但是，这样的写法存在问题，在使用一个属性接受多种类型的参数以后，可能会导致后续使用类的过程中不清楚类的属性的值究竟是 String 类型的还是 Int 类型的，比如：
```java
public void main(String[] args){
	//成绩是 String 类型的
	Score score = new Score("数据结构与算法“，”EP001“，”优秀“);
	// 这里的 score 的 Value 属性存储的是 String 类型，但是由于不清楚，编程人员可能误认为 value 属性是 Integer，这样就会导致编译器报错，正常运行的话还需要进行类型判断，但是这样就增加了工作量。
	Integer i = (Integer) score.getValue();
}
```

所以说这种解决办法虽然可行，但是显然不是最优的。
为例解决以上这个问题，JDK 5 就增加了泛型，能够在编译阶段检查类型安全，大大提升了开发效率。
# 泛型类
泛型类其实就是一个特定类型，我们可以使用一个特殊的名字表示泛型，泛型在定义时并不明确是什么类型，而是需要使用时才会确定对应的泛型类型。
我们可以将一个类定义为一个泛型类：
```java
public class Score<T> { // 泛型类需要使用<>，可以在使用的时候向里面添加 1～N 个类型变量  
    String name;  
    String id;  
    T value; // T 会根据使用的时候提供的类型自动变为对应的类型  
  
    // 这里T 可以是任何类型，但是一旦确定，那么就不能修改了。  
    public Score(String name, String id, T value) {  
        this.name = name;  
        this.id = id;  
        this.value = value;  
    }
	// 获取 Value 值的方法返回类型应该也是泛型参数
    public T getValue() {  
	    return this.value;  
	}  
}
```
**Score 类引入了一个类型变量 T，用尖括号（<>）括起来，放在类名的后面。** 

泛型类可以有多个类型变量，例如，可以定义 Score 类，其中第一个字段和第二个字段使用不同的类型：
```
public class Score<T, U>{
	...
}
```


泛型的使用方法：
```java
public class test {  
    public static void main(String[] args) {  
        // 标准使用方法，在创建对象的时候就在<> 中明确泛型参数是什么类型的。  
        Score<String> score = new Score<>("数据结构与算法"," RP001","优秀");  
	      
    }  
}
```
![[泛型使用过程中的优势.png]]

可以看到，如果想要获取泛型参数，在编写代码过程中编译器会提示泛型参数对应的类型，这样就能避免程序员不清楚类型。
泛型类将数据类型的确定控制在了编译阶段，在编写代码的时候就能明确泛型的类型，如果类型不符合，就无法通过编译！因为是具体使用对象时才会明确具体类型，所以静态方法中是不能使用的。

不过需要注意一下，我们在方法中使用待确定类型的变量时，因为此时并不明确时什么类型，那么默认会认为这个变量是一个 Object 类型的变量，因为无论具体类型是什么，一定是 Object 类型的子类。还有，不能通过这个不确定的类型变量就去直接创建对象和对应的数组，
![[泛型参数不能直接创建对象或数组.png]]

类型参数可以定义很多个，只需要在 `<T,U,...>` 中使用逗号隔开即可。
```java
public class MultipleGenericClass<A,B,C> {  
    private A a;  
    private B b;  
    private C c;  
      
    MultipleGenericClass(A a, B b, C c) {  
        this.a = a;  
        this.b = b;  
        this.c = c;  
    }  
}
```
那么在使用时，就需要将这三种类型都进行明确的指定：
```java
public class test {  
    public static void main(String[] args) {  
      
        // 多个泛型类参数使用的时候，需要将每个泛型类都指定  
        MultipleGenericClass<Integer,Double,String> m = new MultipleGenericClass<>(1,1.1,"C");  
  
    }  
}
```


具体类型不同的泛型类变量，不能直接接收：
![[使用泛型类过程中需要注意的事项.png]]

使用过程中，如果不知道到底需要使用哪种具体的类型，可以使用`?` 通配符，表示这个泛型参数支持任意类型。
```java
public class test {  
    public static void main(String[] args) {  
  
        Score<?> score1 = new Score<>("高等数学","EP002",90);  
          
    }  
}
```
![[泛型类使用注意事项 2.png]]
但是注意，如果使用通配符，那么由于类型不确定，所以说具体类型同样会变成 Object。如上图所示，这里的 score1.value 属性就是 Object 类型。另外，泛型只支持基本类型的包装类型，如果想要传递基本数据类型，就会报错。
## 泛型方法
上一节介绍了如何定义一个泛型类。还可以定义一个带有类型参数的方法。
```java
class ArrayAlg{
	// 获取到 Array 中间的元素
	public static <T> T getMiddle(T....a){
		return a[a.length/2];
	}
}
```
上面这个方法是在普通类中定义的，而不是在泛型类中。不过，这是一个泛型方法，可以从尖括号和类型变量看出这一点。

**类型变量放在修饰符（也就是 public static）后面，在返回类型的前面。**

可以在普通类中定义泛型方法，也可以在泛型类中定义。

调用这个泛型方法的时候，可以把具体类型包围在尖括号中，放在方法名前面：
```
String middle = ArrayAlg.<String>getMiddle("Hohn","A","public");
```

大多数情况下，==方法调用中可以省略 `<String>` 类型参数==。编译器有足够的信息推断出想要的方法。它将参数的类型和泛型类型 T... 进行匹配，推断出 T 一定是 String，也就是说可以简单的调用。
```
String middle = ArrayAlg.getMiddle("Hohn","A","public");
```

# 泛型与多态
不只是类，包括接口、抽象类，都是可以支持使用泛型的，这里以一个接口使用泛型作为例子：
```java
/**  
 * 在接口中也可以定义泛型类参数，在实现接口的时候进行指定即可  
 * @param <L>  
 */  
public interface Test<L> {  
    L test();  
}
```

在实现接口的时候，可以选择在实现接口的时候明确泛型类型，或者是在实现接口的类中继续使用这个泛型让类的对象明确泛型类型：
```java
public class main {  
    public static void main(String[] args) {  
	    // 需要注意的就是这里创建 A 的对象的时候不用明确泛型类型，直接把 A 当做普通类使用即可
		A a = new A();  
		a.test();
    }  
    // 在实现接口的类里面确定泛型类型  
    static class A implements Test<String> {  
        @Override  
        public String test() {  
            return "test";  
        }  
    }  
    // 实现接口的类继承了来自接口的泛型，交给对象确定泛型类型  
    static class B<T> implements Test<T> {  
        @Override  
        public T test() {  
            return null;  
        }  
    }  
}
```

# 泛型方法

泛型方法的使用更加灵活，不用一定要依存于泛型类使用：
```java
public class Test {  
    public static void main(String[] args) {  
        // 在泛型方法里面输入双引号，编译器自动匹配泛型方法的类型为 String 类型  
        String str= test("123");  
        // 在泛型方法里面输入数字，编译器自动匹配泛型方法的类型为 Integer 类型  
        Integer num = test(123);  
    }  
  
    // 泛型方法的 <> 放在方法的类型前面，不要写在其他地方。  
    public static<T> T test(T t){  
        return t;  
    }  
}
```

泛型方法在使用时自动确定泛型类型，比如我们上面定义的是类型 T 作为参数，同样的类型 T 作为返回值，实际传入的参数是一个字符串类型的值，那么 T 就会自动变为 String 类型，因此返回值也是 String 类型。

实际泛型方法在很多工具类中也有使用，比如 Arrays 的排序方法：
```java
public static void main(String[] args) { 
    // 测试使用 Arrays 里面的排序方法，这是一个泛型方法  
    Integer[] arr = new Integer[] {1,3,4,2,7,6,5,9,0};  
    
    // 如果想要正序排列，可以直接使用 Arrays 工具类的 sort 方法  
    Arrays.sort(arr);  
    System.out.println(Arrays.toString(arr));  
    
    // 如果想要倒序排列，就需要使用 sort 的泛型方法，泛型参数是一个比较器  
    // 由于这个比较器是一个接口，直接使用的话需要实现里面的方法，目的是以某种方式排序数组。  
    Arrays.sort( arr,new Comparator<Integer>() {  
        @Override  
        public int compare(Integer o1, Integer o2) {  
            // 如果想要倒序排序，那么比较器返回的就是 o2 - o1            return o2-o1;  
        }  
    }); 


	// 另外，这里可以和前面讲解的 Lambda 表达式结合起来，因为是只有一个抽象方法的接口 new 对象
	// Arrays.sort(arr, (o1,o2) -> (o2-o1))
    System.out.println(Arrays.toString(arr));  
}
```

因此，泛型实际上在很多情况下都能极大的方便我们对于程序的代码设计。

# 泛型的界限
现在有一个新的需求，现在没有 String 类型的成绩了，但是成绩仍然可以是整数，也可能是小数，这时我们不希望用户将泛型指定为除了数字类型以外的其他类型，我们就需要使用泛型的上界定义：
```java
/**  
 * T extends Number 就指定了 T 泛型类型只能是继承自 Number 类型的字类  
 * 这个时候如果再想使用 String 类型作为 T 的话编译器就会报错  
 * 这样就能限制住泛型的类型，让使用者不是所有的类型都能成为 T  
 */public class Score<T extends Number> {  
     private String name;  
     private String id;  
     private T score;  
  
     public Score(String name, String id, T score) {  
         this.name = name;  
         this.id = id;  
         this.score = score;  
     }  
     public T getScore() {  
         return score;  
     }  
}
```
**只需要在泛型变量的后面添加 `extends` 关键字即可指定上界**。使用时，具体类型只能是我们指定的上界类型或者上界类型的子类型，不能使用其他类型，否则一律报错。

在这里我们为什么使用关键字 extends 而不是 implements？下面的记法：
```
<T extends BoundingType>
```
表示 T 应该是限定类型（bounding type）的子类型（subtype）。==T 和限定类型可以是类，也可以是接口。== 选择关键字 extends 的原因是它更接近子类型的概念，并且 Java 的设计者也不打算在语言中添加一个新的关键字（如 sub）。

一个类型变量或通配符可以有多个限定，例如：
```
T extends Comparable & Serializable
```
==限定类型用 “&” 分隔，而逗号用来分隔类型变量。==

同样，**在使用变量的时候，泛型通配符 `?` 也支持泛型的界限**：
```java
public static void main(String[] args) {  
    // 在使用泛型变量的时候，泛型通配符也支持泛型的界限  
    Score<? extends Integer> score = new Score<>("1","2",40);  
}
```

![[泛型界限 extends 的使用.png]]
如果不按照限定的范围使用，编译器就会报错，这样就通过泛型程序设计，把类型不清楚的问题提前到了代码编写阶段，避免了测试后才发现类型不匹配的问题。当然，泛型方法也是可以使用泛型界限的。

## 泛型的下界
那么，泛型既然有上界，有没有下界呢？答案是肯定的。

**但是，泛型类和泛型方法都是不能使用泛型的下界的，只有通配符处可以使用泛型的下！**
```java
public static void main(String[] args) {  
    // 在使用泛型变量的时候，泛型通配符也支持泛型的界限。  
    // 泛型上界的使用，用 extends 关键字  
    Score<? extends Integer> score = new Score<>("1","2",40);  
  
    // 在使用泛型变量的时候，泛型通配符支持泛型的下界  
    // 使用 super 关键字，表达的含义和 extends 相反，只能使用指定界限的本身或父类  
    // 这里指定 super Object，由于 Object 没有父类，所以只能是 Object 类型本身。  
    // Score<? super Object> score1 = new Score<>("2","2",20);  
  
    }
```

那么，定义了上界的泛型参数实际类型是根据使用的时候确定的？还是由上界决定的呢？
```java
public static void main(String[] args) {  
    // 在使用泛型变量的时候，泛型通配符也支持泛型的界限。  
    // 泛型上界的使用，用 extends 关键字  
    Score<? extends Integer> score = new Score<>("1","2",40);  

    //
	Integer num = score.getScore();  
}
```
通过编译器测试可以看到，不管是类型通配符`?`，还是泛型类，只要指定了泛型参数的上界，那么使用的时候就会根据泛型参数的上界来决定 T 的类型。

但是定义下界就不一样了，因为定义下界以后，最高还是能到 Object 类型。

> 最后，通过给泛型设置界限，就能够更加灵活地控制泛型的具体类型的范围。

# 类型擦除
现在我们已经了解到了如何使用泛型，那么泛型到底是如何实现的呢，程序编译以后是什么样子的？
```java
public abstract class A<T>{
	abstract T test(T t);
}
```
实际上在 Java 中不是真的有泛型类型（而是为了兼容之前的 Java 版本而推出的功能）因为所有的对象都是属于一个普通的类型，一个泛型类型编译之后，实际上会直接使用默认的类型：
```java
public abstract class A{
	abstract Object test(Object t); // 默认就是 Object 类型
}
```

当然，如果我们给类型变量设定了上界，那么会从默认类型变成上界定义的类型：
```java
public abstract class A<T extends Number>{
	abstract T test(T t);
}
```
那么编译之后：
```java
public abstract class A{
	abstract Number test(Number t);
}
```
**因此，泛型其实仅仅是在编译阶段进行类型检查，当程序在运行的时候，并不会真的去检查对应类型，所以哪怕我们不去指定类型也可以创建含有泛型类的对象。** 因为在程序运行的时候就会将泛型类型擦除。
