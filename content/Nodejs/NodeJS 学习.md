## 初识NodeJS

Node.js 是一个基于 Chrome V8 引擎的 JavaScript 运行环境。
- 浏览器是 JavaScript 的前端运行环境
- Node.js 是 JavaScript 的后端运行环境
- Node.js 中 无法调用 DOM 和 BOM 等浏览器内置API

# npm与包

## 包

**什么是包？**
Node.js 中的第三方模块又叫包。
不同于Node.js 中的内置模块与自定义模块，包是由第三方个人或团队开发出来的，免费供所有人使用。

**如何下载包？**
npm，Inc. 公司旗下有一家著名网站 ：www.npmjs.com，是全球最大的包共享平台，可以从这个网站上搜索到任何需要的包。目前这个网站上约有 120万个包供我们使用。

在安装Node.js 后，会安装一个 npm(Node Packer Manager) 包管理工具，使用这个npm 包管理工具就可以从 https:/registry.npmjs.org/ 服务器中将需要的包下载到本地。

**初次安装包以后多了哪些文件？**

初次安装包完成以后，在项目文件夹下多了一个叫做 node_modules 的文件夹和 package-lock.json 的配置文件。

- 其中，node_modules 文件夹用来存放所有已经安装到项目中的包，require() 导入第三方包的时候，就是从这个目录查找并加载包的。
- package-lock.json 配置文件用来记录 node_modules 目录下的每一个包的下载信息，例如包的名字、版本号、下载地址等。


 **如何安装指定版本的包？**
 默认情况下，使用npm install 命令安装包的时候，会自动安装最新版本的包。如果需要安装指定版本的包，可以在包名之后，通过@符号指定具体的版本，例如：
 
 ```node
 npm i moment@2.22.2
```

**包的语义化版本规范：**
包的版本号是以 “点分十进制” 形式进行定义的，总共有三位数字，例如 2.24.0
- 第1位数字：大版本
- 第2位数字：包的功能版本
- 第3位数字：Bug修复版本
- 版本号提升的规则：只要前面的版本号增长了，则后面的版本号归零。

### 包管理配置文件 package.json
npm规定，在项目根目录中，必须提供一个叫做 package.json 的包管理文件。用来记录与项目有关的一些配置信息，例如：
- 项目的名称、版本号、描述等
- 项目中都用到了哪些包
- 哪些包只在开发期间会用到
- 哪些包在开发和部署时都需要用到

今后在项目开发过程中，一定要把 node_modules 文件夹，添加到 .gitignore 忽略文件中。

**如何快速创建 package.json**
npm提供了一个快捷命令，可以在执行命令时所处的目录中，快速创建这个配置文件：

```JS
npm init -y
```

注意：上述命令只能在英文目录下运行，项目文件夹名称一定要使用英文命名，**不要使用中文，不能出现空格**。

**dependencies节点**
package.json 文件中，有一个 dependencies 节点，专门用来记录使用 `npm install` 命令安装了哪些包。

**如何一次性安装所有的包**
当我们拿到一个剔除了 node_modules 的项目以后，需要先把所有的包下载到项目中，才能将项目运行起来。

可以运行 npm install 命令一次性安装所有的依赖包。

> 这就解释了为什么我从Github上 Download 的 Hexo 框架还需要在项目目录下面运行 `npm install` 命令，原来是为了安装 hexo 这个框架所需要的依赖包。

**如何卸载包？**
可以运行 `npm uninstall` 命令，卸载指定的包。

```JS
npm uninstall moment
```

注意：npm uninstall 命令执行成功以后，会把卸载的包，自动从 package.json 的 dependencies 中移除掉。也就是说，后续发布部署的时候，别人安装的时候不会自动下载这个已经被删除的包。

**devDependencies节点**
如果某些包只在项目开发阶段会用到，在项目上线之后不会用到，则应该把这些包记录到 devDependencies 节点中。
与之对应的，如果在开发和项目上线之后都会用到，那么就需要把这些包记录到 dependencies 节点中。

如果在安装包的时候，在后面加上 `-D` 的参数，则表明把这个包记录到 devDependencies 中。

哪些包安装到开发依赖节点，哪些包安装到上线依赖节点，在npm网站上搜索包，找到安装教程，放心使用即可。

**解决包下载速度慢的问题**
为了更方便的切换下包的镜像源，可以安装 nrm 这个工具，利用 nrm 提供的终端命令，可以快速查看和切换下包的镜像源。

```
# 通过npm 包管理器，将 nrm 安装为全局可用的工具
npm i nrm -g

# 查看所有可用的镜像源
nrm ls

# 将下包的镜像源切换为 taobao 镜像
nrm use taobao
```

### 包的分类
使用npm包管理工具下载的包，总共可以分为两大类：
- 项目包
	- 被安装到项目的 node_modules 目录中的包，都是项目包
		- 开发依赖包：devDependencies节点中的包
		- 核心依赖包：dependencies节点中的包
- 全局包
	- 在执行npm install 命令时，如果提供了 -g 参数，则会把包安装为全局包。
	- 全局包的安装和卸载都是在最后加上 `-g` 参数
	- 只有工具性质的包，才有全局安装的必要性。因为它们提供了好用的终端工具。
	- 判断某个包是否需要全局安装，可以参考官方提供的使用说明即可。

**规范包的结构**
一个规范的包，组成结构必须符合以下3点要求：
1. 包必须在 node_modules 中以单独的目录而存在
2. 包的顶级目录下必须包含 package.json 这个包配置文件
3. package.json 中必须包含 name, version, main 这三个属性，分别代表包的名字、版本号、包的入口。
